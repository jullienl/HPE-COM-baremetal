# HVM (HPE Morpheus VM Essentials) networking

This document details the HVM network model used by `HVM_provisioning.yml`: how the management interface is prepared during install, how a second NIC is teamed for redundancy after the cluster join, and how to run a separate (dedicated) compute network. For the general project overview, see the main [readme](../readme.md).

## Base management interface

For HVM, the network configuration follows the HPE VM Essentials requirements. The HPE `hpe-vm` installer builds the VME management and compute networks as **Open vSwitch (OVS) bridges** on top of a physical management interface, so the OS installation seed assigns the management IP to a **single plain management NIC** (renamed to `mgmt0`) and does **not** pre-build a Linux bond (a pre-built kernel bond would prevent OVS from enslaving the ports, failing with `Device or resource busy`). The NIC is selected generation-independently by MAC from the COM inventory (see `bond_member_selection`/`bond_member_adapter_match` in `vars/HVM_vars.yml`). When the `mgmt_vlan` variable is set to a value greater than 0, the management IP is placed on a tagged VLAN interface (`mgmt0.<vlan>`); otherwise it is placed directly on `mgmt0`. The management (tagged) and compute (untagged) interfaces are then passed to the HPE VM Essentials Manager when the host joins the HVM cluster.

## Management-link redundancy (second NIC teaming)

When a **second management NIC is cabled**, the playbook adds it to an **active-backup native OVS bond** (`mgmtbond` = `mgmt0` + `mgmt1`) on the VME `mgmt` bridge, giving management-link redundancy without any switch-side configuration. This is controlled by `hvm_second_nic_team` (default `true`) and `hvm_mgmt_bond_mode` (default `active-backup`) in `vars/HVM_vars.yml`, and requires `bond_member_count >= 2` so a second port MAC is derived from the COM inventory. The autoinstall seed renames the second port to a stable `mgmt1` (plain, no IP), and a dedicated post-join play (Play 4) builds the bond **after** the VME Manager has created the OVS `mgmt` bridge (the bond must be a *native OVS* bond, not a Linux/networkd bond, so OVS can own the ports). The behaviour is safe and idempotent: a host with a **single cabled NIC is a complete no-op** (the second NIC is only teamed when it has an active link/carrier), and the bond is created in a single atomic `ovs-vsctl` transaction so the live management link is not lost during reconfiguration. Set `hvm_mgmt_bond_mode` to `balance-tcp` (LACP) only if the upstream switch ports are configured as a matching port-channel; otherwise keep `active-backup`. This management-link redundancy path is **validated on hardware** with a 2-NIC host (`mgmtbond` = `mgmt0` + `mgmt1`, active-backup).

## Converged vs separate compute (VM) network

By default the compute (VM) network shares the same physical uplink and OVS bridge as management (the HPE `hpe-vm -i mgmt0 -c mgmt0` converged model), so teaming the second management NIC **also protects all VM/compute VLAN traffic** — no extra configuration is needed. Play 4 is generic: for each entry in `hvm_nic_teams` it discovers *which* OVS bridge owns the primary uplink at run time (`ovs-vsctl port-to-br`) and teams the cabled secondary there, so the bridge name never has to be known in advance.

For hosts with **dedicated compute NICs** (deployed with a separate compute interface, `hpe-vm ... -c comp0`), set `hvm_separate_compute_network: true`: the seed then renames the dedicated port(s) to `comp0` (+ `comp1`), `vme_compute_net_interface` becomes `comp0` (so the VME Manager builds a separate compute bridge), and Play 4 additionally teams a cabled `comp1` with `comp0` (`compbond`). The dedicated compute NIC(s) are selected via `hvm_compute_adapter_match` (a different adapter) or, if left empty, the ports that follow the management ports on the same adapter (`hvm_compute_nic_count`).

**NIC-count requirement**: the fully-redundant separate-compute layout (the defaults `bond_member_count: 2` + `hvm_compute_nic_count: 2`, i.e. both roles teamed) needs **4 cabled NICs** (2 management + 2 compute), and when `hvm_compute_adapter_match` is empty those 4 ports must be on the same adapter; a non-redundant separate-compute layout needs only 2 NICs (set `bond_member_count: 1` and `hvm_compute_nic_count: 1`). This separate-compute path is **opt-in and untested pending 4-NIC hardware**; the converged default is the validated path.
